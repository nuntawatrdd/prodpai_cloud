# prodpai_cloud — Prod-Pai Cloud Infrastructure

Infrastructure as Code (Terraform) on AWS for the **Prod-Pai Cloud DevSecOps** project.

It deploys the web app built in [`prodpai_app`](https://github.com/nuntawatrdd/prodpai_app) behind an Application Load Balancer, adds a security layer (AWS WAF, Falco runtime detection, automatic incident response), and ships an infrastructure **dashboard** that shows the live state of the AWS account.

## Architecture

```text
                              Internet
                                 │
                                 ▼
                ┌────────────────────────────────┐
                │ AWS WAFv2 (REGIONAL web ACL)   │  rate limit · SQLi · common rules
                └────────────────┬───────────────┘
                                 ▼
              ┌──────────────────────────────────────┐
              │ Application Load Balancer  (:80)     │  public subnets, 2 AZs
              │   /dashboard*  ─► dashboard TG :5000 │
              │   default      ─► app TG  (/health)  │
              └───────┬──────────────────┬───────────┘
                      │                  │
        ┌─────────────▼───────┐   ┌──────▼─────────────┐
        │ Auto Scaling Group  │   │ Dashboard EC2      │   private subnets
        │ 2–3 × t3.small      │   │ t3.micro, Flask    │   (egress via NAT)
        │ Docker app + Falco  │   │ + Gunicorn :5000   │
        └─────────────┬───────┘   └──────┬─────────────┘
                      │                  │ reads via S3 Gateway Endpoint
     Falco alert      │                  ▼
     (Falcosidekick)  ▼            ┌───────────────┐   writes   ┌─────────────────────────┐
        CloudWatch Logs /falco/alerts  │ S3 prod-pai-logs │ ◄──────── │ Lambda Infra-Aggregator │ ◄─ "Sync AWS" button
                      │            └───────────────┘            └─────────────────────────┘
                      ▼  (Critical / Emergency only)
        Lambda quarantine_taken_instance
          detach from ASG → EBS forensic snapshot → isolate SG → tag Compromised
```

**Image pipeline:** `prodpai_app` CI pushes `prodpai_cloud:latest` to ECR → ASG instances pull and run it at boot (`userdata.sh`).

**AMI pipeline:** Terraform launches a temporary *image builder* instance, installs Falco on it, bakes an AMI from it, uses that AMI in the Launch Template, then terminates the builder.

## Terraform resources

| File | Resources |
|---|---|
| `terraform.tf` | `aws` provider `~> 5.0`, Terraform `>= 1.5.0`, **S3 backend** (`prodpai-tfstate-storage`, key `prodpai/terraform.tfstate`, `us-east-1`); default tags `Course`, `ManagedBy` |
| `vpc.tf` | VPC `10.0.0.0/16`; 2 public subnets; 2 private subnets; Internet Gateway; Elastic IP + NAT Gateway (in public subnet 0); public and private route tables |
| `security.tf` | `allow-instance-sg`, `allow_http-alb`, `ec2-compromise-isolatation-sg`, `dashboard-ec2-sg` |
| `key.tf` | `tls_private_key.genKey` (RSA 4096) → `aws_key_pair.deployer` (`prodpai-key`) |
| `ec2.tf` | Ubuntu 24.04 AMI lookup (Canonical), ECR repo lookups, image-builder `aws_instance`, `aws_ami_from_instance`, launch template, `aws_autoscaling_group`, `null_resource.terminate_builder`, dashboard `aws_instance` |
| `lb.tf` | ALB, app target group (`/health`), HTTP:80 listener, dashboard target group (`:5000`, `/dashboard/health`), attachment, listener rule `/dashboard*` |
| `waf.tf` | WAFv2 web ACL (3 rules) + ALB association |
| `lambda.tf` | `quarantine_taken_instance`, `prod-pai-Infra-Aggregator`, log group `/falco/alerts`, log stream `falco-events`, subscription filter, Lambda permission, S3 gateway VPC endpoint |
| `outputs.tf` | `lb_domain_name_http`; `aws_instances` / `aws_autoscaling_group` data sources that read the *real* state from AWS |

Both Lambdas and all EC2 instances use the pre-existing AWS Academy IAM role **`LabRole`** and instance profile **`LabInstanceProfile`**; Terraform does not create IAM resources.

## Network design

| Item | Value |
|---|---|
| VPC CIDR | `10.0.0.0/16` |
| Public subnets | `10.0.1.0/24`, `10.0.11.0/24` (AZ a, b) — ALB, NAT Gateway, image builder |
| Private subnets | `10.0.2.0/24` (`us-east-1a`), `10.0.12.0/24` (`us-east-1b`) — ASG instances and dashboard |
| Egress from private | NAT Gateway (single, in public subnet 0) |
| S3 access from private | Gateway VPC endpoint on the private route table |

ASG instances have **no public IP** (`associate_public_ip_address = false`) and are reachable only through the ALB.

### Security groups

| Group | Inbound | Outbound |
|---|---|---|
| `allow-instance-sg` (ASG + builder) | 80 from ALB SG; 22 and 5000 from `cidr_allow_all` (`0.0.0.0/0`) | all |
| `allow_http-alb` (ALB) | 80 from `0.0.0.0/0` | all |
| `dashboard-ec2-sg` | 5000 from ALB SG | all |
| `ec2-compromise-isolatation-sg` (quarantine) | **none** | **none** |

## Security layers

### 1. AWS WAF (`waf.tf`)

Regional web ACL attached to the ALB; default action **allow**.

| Priority | Rule | Action |
|---|---|---|
| 1 | `web_rate` — rate-based, **100 requests / 60 s per IP**, scoped to **GET** requests | Block |
| 2 | `AWSManagedRulesSQLiRuleSet` (SQL injection) | managed (no override) |
| 3 | `AWSManagedRulesCommonRuleSet` (XSS, LFI and other common exploits) | managed (no override) |

All rules publish CloudWatch metrics and sampled requests.

### 2. Runtime detection with Falco (`scripts/falco_setup.sh`)

Installed on the image-builder instance (and therefore on every ASG instance baked from its AMI):

- Falco from the official apt repository, using the **modern eBPF** driver (`falco-modern-bpf`); JSON output enabled; HTTP output pointed at Falcosidekick (`http://localhost:2801/`).
- **Falcosidekick** (latest release) running as a systemd service, forwarding alerts to CloudWatch Logs: log group `/falco/alerts`, stream `falco-events`.
- Three custom rules in `/etc/falco/falco_rules.local.yaml`, all priority **Critical**:
  - **Host System Binary Tampering** — writes under `/bin`, `/sbin`, `/usr/bin`, `/usr/sbin` (except apt/dpkg/yum/rpm)
  - **Unauthorized Web Root Modification** — writes under `/var/www` (except git/composer/npm)
  - **Shell Spawned by Web User** — `bash/sh/dash/zsh` started by `www-data`, `nginx` or `apache`

At boot, `userdata.sh` sets the hostname to the EC2 instance ID (so alerts identify the instance) and restarts Falco and Falcosidekick.

### 3. Network isolation

Private subnets, no public IPs on app instances, ALB-only ingress on port 80.

## Incident response (quarantine)

Falco alert → Falcosidekick → CloudWatch Logs `/falco/alerts` → **subscription filter** `{ $.priority = "Critical" || $.priority = "Emergency" }` → Lambda **`quarantine_taken_instance`** (Python 3.10, `quarantine_instance.py`).

For each log event the Lambda treats the instance as compromised if the priority is `Critical`/`Emergency`/`Alert`, **or** the rule is one of `Terminal shell in container`, `Run shell untrusted`, `Launch Privileged Container`, `Write below etc`. The Falco `hostname` must be an instance ID (`i-…`). It then:

1. **Detaches the instance from its Auto Scaling Group** with `ShouldDecrementDesiredCapacity=False`, so the ASG launches a replacement immediately.
2. **Creates EBS snapshots of every attached volume** for forensics, tagged `Case=IncidentResponse`, `CompromisedInstanceId=<id>`, `Name=forensic-<id>-<device>`.
3. **Moves the instance into the isolation security group** (no inbound, no outbound — an "air gap").
4. **Tags it** `SecurityStatus=Compromised`.

Steps 1–2 are best-effort (a failure is logged and isolation still happens). The Lambda env var `ISOLATED_SG_ID` is set by Terraform.

> The `HEALTHCHECK` in `prodpai_app` deliberately avoids a shell so the *Shell Spawned by Web User* rule is not triggered by normal operation.

## Dashboard

A read-mostly web UI that visualises the live infrastructure. Served at **`http://<alb-dns>/dashboard`**.

### Components

| Component | Role |
|---|---|
| **Lambda `prod-pai-Infra-Aggregator`** (`dashboard_aggregator.py`, 120 s timeout, 512 MB) | Sweeps the AWS region and writes one JSON document to `s3://prod-pai-logs/dashboard/current_infra.json`. Invoked **only** from the Sync button — no EventBridge or schedule. |
| **S3 bucket `prod-pai-logs`** | Holds `current_infra.json`, the cost cache and the incident prefix. |
| **Dashboard EC2** (`t3.micro`, private subnet, container on `:5000`) | Flask app under Gunicorn (`gthread`, 1 worker, 16 threads). Reads the JSON through the S3 gateway endpoint; does not call AWS APIs itself except the Sync button. |
| **ALB listener rule** `/dashboard*` | Routes to the dashboard target group (health `/dashboard/health`). |


### HTTP endpoints

All routes live under `/dashboard` because the ALB forwards the path unchanged.

| Method & path | Purpose |
|---|---|
| `GET /dashboard` | The HTML page |
| `GET /dashboard/health` | ALB health check — always `200`, never touches S3 |
| `GET /dashboard/api/data` | Latest infrastructure JSON (or a `waiting` state if the first sync has not happened) |
| `POST /dashboard/api/force-refresh` | Invoke the aggregator Lambda synchronously. `409` if a sync is running, `429` + `Retry-After` during the 30 s cooldown, `502`/`500` on failure |
| `GET /dashboard/api/events` | Server-Sent Events stream; emits `change` when the S3 ETag changes, heartbeat every 15 s, closes after 300 s (browser reconnects) |

Environment variables (set by `setup_dashboard.sh`): `INFRA_S3_BUCKET`, `INFRA_LAMBDA_NAME`, `AWS_DEFAULT_REGION`. Optional: `SYNC_COOLDOWN_SECONDS` (30), `GUNICORN_THREADS` (16), `PORT` (5000).

> The Sync button is **not authentication**: anyone who can open the dashboard can press it (rate-limited by the cooldown). The cooldown lock is in-memory, which is valid only because there is one Gunicorn process and one dashboard instance.

## GitHub Actions workflows

Both are `workflow_dispatch` (manual) and read `.github/config.env`:

```env
AWS_REGION=us-east-1
ASG_NAME=prod-pai-env-
TF_STATE_BUCKET=prodpai-tfstate-storage
APP_ECR_REPOSITORY=prodpai_cloud
DASHBOARD_ECR_REPOSITORY=prodpai_dashboard
```

| Workflow | File | Steps |
|---|---|---|
| **Terraform Deploy Infra** | `deploy.yml` | checkout → load config → AWS credentials → ECR login → **build & push the dashboard image** (`prodpai_dashboard:<sha>` and `:latest`) → install Terraform 1.9.8 → remove cached `.terraform` / lock file → `terraform init -upgrade` → `terraform apply -auto-approve` |
| **Patch & Rollout ASG** | `patch.yaml` | find the ASG by name prefix → list its instances → `terminate-instance-in-auto-scaling-group --no-should-decrement-desired-capacity` for each, one at a time, so the ASG replaces each with a fresh instance that pulls the latest app image |

**Required secrets:** `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` (AWS Academy credentials expire about every 4 hours).

## Prerequisites

- An AWS account / AWS Academy Learner Lab in `us-east-1` with the `LabRole` role and `LabInstanceProfile` instance profile.
- Existing **ECR repositories**: `prodpai_cloud` (app image) and `prodpai_dashboard` (dashboard image).
- Existing **S3 bucket** `prodpai-tfstate-storage` for Terraform state.
- Existing **S3 bucket** `prod-pai-logs` for dashboard data (Terraform does not create it).
- At least one app image pushed by the `prodpai_app` CI.
- Local runs: Terraform ≥ 1.5, AWS CLI with credentials, and (for the key file) a `~/.ssh` directory.

## Deploy step by step

1. **Push the app image.** Merge to `main` in `prodpai_app` and wait for CI to push `prodpai_cloud:latest` to ECR.
2. **Add secrets** to this repository (the three AWS values).
3. **Run "Terraform Deploy Infra"** from the Actions tab. It builds the dashboard image, then applies Terraform. This takes a while: Falco is installed on the builder, an AMI is created, the ASG warms up.
4. **Open the app:** take `lb_domain_name_http` from the Terraform output. The Todo app is at `/`, the dashboard at `/dashboard`.
5. In the dashboard click **Sync AWS** to run the aggregator for the first time.
6. **Ship a new app version:** after `prodpai_app` pushes a new `latest`, run **Patch & Rollout ASG**.

Running locally instead of Actions:

```bash
aws configure
terraform init
terraform plan
terraform apply
```

Edit `TARGET_URL` in each script to your ALB DNS name first.

```bash
k6 run scripts/test/alb_load_test.js          # 30 VUs for 10 min, fails if >1% requests fail

```

## Cost

Main cost drivers: **NAT Gateway** (hourly + data), **Application Load Balancer**, **EC2** (2–3 × `t3.small`, 1 × `t3.micro`), **WAF** (web ACL + rules), EBS and forensic snapshots. The dashboard shows both actuals (if permitted) and an estimate. Destroy the stack when you are not using it.

## Known issues & caveats

- **`patch.yaml` variable mismatch:** the workflow reads `ASG_NAME_PREFIX`, but `config.env` defines `ASG_NAME`, so the prefix is empty. Rename one so they match before relying on this workflow.
- **`patch.yaml` delay:** it runs `sleep 300` (5 minutes) while the comment says 30 seconds.
- **`s3.tf` is empty:** the `prod-pai-logs` bucket must be created outside Terraform.
- **Aggregator env:** the Terraform Lambda definition sets only `S3_BUCKET`. The aggregator can also use `APP_TG_ARN` / `DASH_TG_ARN` to decide which target groups count towards "healthy"; they are not set here.
- **Permissive security group:** `allow-instance-sg` opens ports 22 and 5000 to `0.0.0.0/0` (the instances are in private subnets without public IPs, but tighten this anyway).
- **HTTP only:** the ALB listener is port 80; there is no HTTPS or certificate.
- **Single NAT Gateway:** one AZ's failure removes outbound internet for both private subnets.
- **Private key handling:** the generated key pair lives in Terraform state; keep the state bucket private.
- **Dashboard front-end** loads fonts and icons from public CDNs (jsDelivr, unpkg).
- **AWS Academy limits:** Cost Explorer is usually denied, credentials expire every ~4 hours, and `LabRole` is fixed.

## Tear down

```bash
terraform destroy
```

Also delete, if no longer needed: forensic EBS snapshots created by the quarantine Lambda, the AMI created from the builder, and the `prod-pai-logs` bucket contents. The state bucket and ECR repositories are not managed by this configuration.
